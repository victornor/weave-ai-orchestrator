# M1 — A conductor you can talk to, from anywhere

Demonstrates PLAN §22 M1: operator password and session tokens, `weave login` and contexts, an
authenticated public listener with self-signed TLS, the wake queue and run engine, the Claude
runtime adapter with session resume, tickets and decisions, the `cli` and `web` channels, and cost
attribution — proven from a second machine.

**Takes:** about 20 minutes. **Needs:** two machines (or two shells and a hostname that is not
loopback), Node ≥ 22 on the daemon host, `claude` installed and logged in there.

Throughout: `DAEMON` = the machine running the daemon, `CLIENT` = your laptop.

---

## 1. Build and start the daemon (DAEMON)

```bash
pnpm install && pnpm build
pnpm --filter @weave-ai/ui build

cat > ~/.config/weave/daemon.yaml <<'YAML'
version: 1
http:
  listen: 0.0.0.0:7433
  publicUrl: https://daemon.local:7433
  tls:
    mode: self-signed
    domains: [daemon.local]
auth:
  loopbackTrusted: false
YAML

weave daemon start
weave daemon status
```

Expected: `weave daemon status` prints the pid and the health payload with
`operatorConfigured: false`, `tlsMode: self-signed`, `workspaces: []`.

Now prove the guard: stop the daemon, remove the password requirement escape hatch, and confirm it
refuses to listen unauthenticated off loopback.

```bash
weave daemon stop
node packages/server/dist/bin.js          # foreground, still no operator
```

Expected: it exits with
`refusing to listen on 0.0.0.0: no operator password is set. Run 'weave daemon set-password', bind to 127.0.0.1, or set auth.loopbackTrusted for a loopback-only daemon.`

Set the password and start again:

```bash
weave daemon start
weave daemon set-password            # prompts twice; minimum 8 characters
```

Expected: `operator configured — sign in with 'weave login https://daemon.local:7433'`. Under the
covers this is `POST /api/auth/setup`, which is refused once an operator exists.

## 2. Create a workspace (DAEMON)

```bash
weave init ~/work/acme --prefix ACME --name "Acme Labs"
weave workspace list
weave runtime list
```

Expected: `workspace ready acme`, the workspace listed, and `claude` shown as `available` with a
version and a path. `weave init` also writes the workspace as the default for this machine's context,
so later commands need no `-w acme`.

Check the layout it scaffolded:

```bash
ls ~/work/acme
# workspace.yaml  .weave/  conductor/  knowledge/  roles/  workers/  projects/  archive/
ls ~/work/acme/knowledge/workspace
# WORKSPACE.md  SHARED.md  decisions.md
```

## 3. Add a project (DAEMON)

Use any repo you can clone. Roles are hired later (M2), so nothing will pick work up yet — that is
the point of this step.

```bash
weave project add git@github.com:acme/api.git --runtime claude
weave project list
weave ticket list
```

Expected: project `api` in state `ready`, and one `scout` ticket **ACME-1 "Describe project api"** in
`backlog` — it has no role to run on yet.

## 4. Sign in from the second machine (CLIENT)

```bash
weave login https://daemon.local:7433 --pin --device laptop
```

Expected: the certificate subject and validity are printed, then the SHA-256 pin, then a password
prompt, then `signed in as operator -> context daemon.local` with the workspace filled in.

```bash
weave context list        # * daemon.local  https://daemon.local:7433  acme  token  yes
weave doctor
```

Prove that plaintext is refused:

```bash
weave login http://daemon.local:7433
# refusing to send a password in plaintext to http://daemon.local:7433; use https or pass --insecure
```

## 5. Talk to the conductor from the client

```bash
weave say "create a ticket to add a README badge in project api"
```

Expected: within a few seconds the conductor replies in plain language — something like "Created
ACME-2 'Add a README badge'. There is no role hired for `api` yet, so it is sitting in the backlog;
say the word and I'll propose one." Then:

```bash
weave ticket list
weave ticket show ACME-2
weave runs list
```

Expected: `ACME-2` exists, kind `task` or `change`, status `backlog`, no assignee. `weave runs list`
shows one succeeded run for the conductor with token counts and a cost.

The web app proves the same state: open `https://daemon.local:7433` in a browser, accept the
self-signed certificate, sign in, and the Chat view shows the same exchange with the ticket chip.

## 6. Session resume across turns

```bash
weave say "what was the last thing I asked you?"
```

Expected: the conductor recalls the badge ticket without being told again. Confirm it is the *same*
session rather than a rebuilt prompt:

```bash
weave runs list --limit 5
weave runs show <second-run-id>
```

Expected: the second run's transcript opens with `session.resumed`, not `session.started`, and the
session id matches the first run's.

## 7. Restart mid-run is a non-event

Start something that will take a while, then pull the plug on the daemon:

```bash
# CLIENT
weave say --no-wait "summarise what you know about the api project, in detail"

# DAEMON, while the run is going
weave runs list -s running          # note the run id
weave daemon stop
weave daemon start
```

Then on the client:

```bash
weave runs show <run-id>
weave runs list --limit 5
```

Expected: the interrupted run has status `interrupted`; the supervisor's boot recovery re-queued its
wake exactly once, so a *new* run for the same agent follows and succeeds. Nothing in the chat thread
is lost, and no wake is dropped or duplicated.

## 8. Change the conductor's model

```bash
weave weaver show
weave runtime models claude
weave weaver set-model <some-model-id>
weave say "hello again"
weave runs list --limit 1
```

Expected: `weave weaver show` reflects the new model immediately, and the *next* run — not the one in
flight — reports that model in `weave runs show`. `weave weaver set-model default` returns to the
runtime default. `weave weaver reset-session` starts a fresh session, after which the conductor no
longer recalls turn 1 (its context is rebuilt from the knowledge base instead).

## Acceptance checklist

- [ ] The daemon refuses a non-loopback listener with no operator password.
- [ ] `weave login --pin` from a second machine stores a context and every later command works remotely.
- [ ] `weave say "create a ticket…"` creates a real ticket that stays `backlog`, and the conductor says why.
- [ ] Restarting the daemon mid-run marks the run `interrupted` and retries the wake once; nothing is lost.
- [ ] Turn 2 resumes the same session (`session.resumed`) and the conductor recalls turn 1.
- [ ] Changing the conductor's model takes effect on the next turn.
- [ ] The web app shows the same state as the CLI.

## Not yet automated

- There is no `conductor` command for TOTP enrolment; it lives in the web app's Settings → Security (M3).
- `weave daemon stop` only stops a daemon that `weave daemon start` launched on that machine. Under
  systemd, use `systemctl --user stop weave-ai.service`.
- `http.tls.mode: acme` is not implemented — use `self-signed`, `files`, or a reverse proxy.
