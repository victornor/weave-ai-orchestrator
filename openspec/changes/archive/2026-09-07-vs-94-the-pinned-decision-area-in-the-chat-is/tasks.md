## 1. The stored height and its clamps

- [x] 1.1 Add `packages/ui/src/lib/decisionHeight.ts` with `readDecisionHeight(): number | null` and `writeDecisionHeight(px: number | null)` over the key `conductor.decisions.height`, every `localStorage` access guarded the way `lib/barVisibility.ts` guards its own; a non-finite, non-positive or unparseable stored value reads as `null`, and `writeDecisionHeight(null)` removes the key. Verify by unit test that a stored `"320"` reads back as `320`, that `"abc"`, `"0"` and `"-5"` all read as `null`, and that a throwing `localStorage` yields `null` rather than an exception.
- [x] 1.2 In the same module export `MIN_PX` (144), `MIN_LIST_PX` (120), `STEP_PX` (24) and `clampHeight(px, { sectionBottom, pageTop })`, returning a rounded height clamped to `[MIN_PX, max(MIN_PX, sectionBottom - pageTop - MIN_LIST_PX)]`. Verify by unit test that a height inside the range is returned rounded and unchanged, that one below returns `MIN_PX`, that one above returns the computed maximum, and that geometry too small to hold both constants returns `MIN_PX` rather than an inverted range.

## 2. The handle and the drag in the chat

- [x] 2.1 In `packages/ui/src/routes/Chat.tsx`, read the stored height into state on mount and give the `<section aria-label="Open decisions">` an inline `style` carrying `maxHeight: 'calc(var(--ac-app-h) * 0.75)'` always and `height: '<n>px'` only when a height is stored, removing the `max-h-[calc(var(--ac-app-h)*0.45)]` utility and keeping `calc(var(--ac-app-h) * 0.45)` as the `maxHeight` while no height is stored. Verify the section carries no `height` and the 45% `max-height` with an empty store, and both the chosen `height` and the 75% `max-height` once one is set.
- [x] 2.2 Render the handle as the section's first child: a `role="separator"` element with `aria-orientation="horizontal"`, an accessible name saying it resizes the decisions area, `aria-valuemin`, `aria-valuemax`, `aria-valuenow`, `tabIndex={0}` and `touch-action: none`, styled as a full-width grab strip on the section's top border. Verify it is inside the section, is the element the top border reads from, and is absent when the section is not rendered.
- [x] 2.3 Record the section's rendered height in a layout effect so `aria-valuenow` reports a real number before the first resize, and have it follow the chosen height afterwards. Verify with a faked section rect that `aria-valuenow` matches the measured height with an empty store and the stored height after a resize.
- [x] 2.4 Implement the drag: `onPointerDown` captures `sectionBottom` and `pageTop` from live rects, calls `setPointerCapture` behind a guard and starts the drag; `pointermove` on `window` sets the height to `clampHeight(sectionBottom - clientY, …)`; `pointerup` on `window` ends the drag and persists the height with `writeDecisionHeight`. Verify by test with faked geometry that dragging up increases the height, dragging down decreases it, and the value written to storage is the height the section ends at.
- [x] 2.5 Implement the keyboard: `ArrowUp`/`ArrowDown` move by `STEP_PX`, `Home` and `End` go to the minimum and the maximum, `Enter` and `Escape` reset, every handled key calls `preventDefault()`, and each resulting height is persisted. Verify each key by test and verify that an unhandled key leaves the height alone and is not prevented.
- [x] 2.6 Implement the reset gesture: `onDoubleClick` on the handle clears the stored height and returns the section to the unresized rendering. Verify the section loses its inline `height`, regains the 45% `max-height`, and that the key is gone from `localStorage`.
