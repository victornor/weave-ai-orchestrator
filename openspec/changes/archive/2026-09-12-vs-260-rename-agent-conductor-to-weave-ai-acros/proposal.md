## Why

captain is renaming this project. VS-258 shipped the path-compatibility resolver and VS-259 renamed the
`conductor` agent kind to `weaver`; this is the last ticket, and it renames the **product**:
`agent-conductor` → `weave-ai`, and the CLI binary `conductor` → `weave`.

Unlike VS-259, nothing here is stored state: no SQLite value, no migration, no directory this ticket
creates. VS-257's scout report and the conductor's follow-up comment both measured the surface and
agree it is mechanical — 27 scoped packages, ~400 TypeScript files, a handful of service constants,
the agent-facing tool names and their prose. The reason it needs its own ticket and its own quiet
window is size and conflict surface, not risk: a rename spread over several merges makes every branch
in between conflict with it twice, so it lands as one pass.

Two things raise the real risk, and the design addresses both. First, `ac_*` MCP tool names are
byte-exact identifiers an LLM matches against its tool schema; the same name is re-spelled in the
registration, in a size-cap `Set`, and in ~104 prose files, and a one-character drift produces an
agent that cannot call a tool and cannot say why. Second, every existing installation on disk is
old-named; VS-258's resolvers must keep finding it after this change, which is the regression that
matters most.

## What Changes

- **Package scope.** `@agent-conductor/*` → `@weave-ai/*` in every scoped `package.json` `name` and
  internal `dependencies` entry, in every TypeScript import specifier, in the root `package.json`,
  `pnpm-lock.yaml` (regenerated by `pnpm install`), `vitest.config.ts`, the Dockerfile, and
  `examples/plugins/echo-channel`. No `tsconfig` `paths` block or `.npmrc` holds the scope, so it is a
  genuine find-and-replace.
- **The CLI binary.** `packages/cli/package.json`'s `bin` key and `packages/cli/src/program.ts`'s
  `.name()`, plus the root `conductor` convenience script and every documented `conductor <command>`
  example. The server's own binary `ac-daemon` → `weave-daemon`.
- **The service identifiers**, each spelled differently today and each easy to miss: `SERVICE_NAME`
  (`agent-conductor.service`), `LAUNCHD_LABEL` (`com.agentconductor.daemon`,
  `packages/release/src/index.ts`) and `MCP_SERVER_NAME` (`agentconductor`, `packages/server/src/mcp.ts`)
  — the last also re-spelled as a literal in `packages/core/src/runs/engine.ts`'s run MCP config.
- **The MCP tool names.** `ac_*` → `weave_*` across the whole registered set, byte-exact in
  `packages/shared/src/tools.ts`, `packages/server/src/tools.ts`, the size-cap `Set` in
  `packages/server/src/mcp.ts`, the agent prompts in `packages/core/src/prompts/`, and every prose site
  that instructs an agent to call a tool.
- **The skills and their install paths.** All nine `skills/agent-conductor-*` directories →
  `weave-ai-*`, with `skills/manifest.json`, the hardcoded install arrays in
  `packages/core/src/workers/home.ts`, and the artifact-playbook path in
  `packages/core/src/artifacts/kit.ts` following.
- **The URL convention.** `conductor://` → `weave://` in its instruction sites. Nothing parses it.
- **Branding prose:** README, `CLA.md`, `LICENSE` header where it names the project, Dockerfile
  header, `CLAUDE.md`, `ee/`, `docs/`, and the shipped `templates/*.tmpl`.

Explicitly **not** changed: the on-disk directory names VS-258 already chose (`.weave`, `weave`,
`weaver`) — changing them would invalidate the resolver that keeps existing installs working;
`AC_*` environment variables; the `conductor`→`weaver` agent-kind identity VS-259 owns; the current
`openspec/specs/**` requirement prose and archived changes; and the repo/org move, remotes and service
reinstall, which are captain's.

**Role ids are out of scope.** Slugs such as `agent-conductor-engineer` do not appear anywhere in the
repo: they are live workspace data — a `roles` row, `tickets.assignee_role_id`, `agents.role_id` and a
`roles/<id>/` directory on disk. Renaming one is a data migration on a running workspace, not a source
change, and doing it blind would orphan every ticket pointing at it.

## Capabilities

### New Capabilities

- `product-rename`: the guarantees this rename makes — no live `@agent-conductor` package name or
  import specifier, one consistent new spelling for the binary, the service, the MCP server, the
  skills and the tool names, an existing old-named installation still found through VS-258's
  resolvers, and a fresh install working end to end under the new names.

### Modified Capabilities

(none — the renamed tool names are the same tools with new identifiers, and VS-258's
`path-compatibility` requirements are satisfied unchanged. `openspec/specs/**` requirement prose is
out of scope, per this change's design.)

## Impact

- **Scope/build**: 27 `package.json` files, ~399 `.ts`/`.tsx` import sites, `pnpm-lock.yaml`,
  root `package.json`, `vitest.config.ts`, `Dockerfile`, `examples/plugins/`.
- **CLI/server identity**: `packages/cli/package.json`, `packages/cli/src/program.ts`,
  `packages/server/package.json`, `packages/server/src/mcp.ts`,
  `packages/release/src/index.ts`, `packages/core/src/runs/engine.ts`, runtime arg tests.
- **Tools**: `packages/shared/src/tools.ts`, `packages/server/src/tools.ts`, and every prose file
  under `skills/`, `templates/`, `docs/`, `packages/core/src/prompts/`.
- **Skills**: `skills/agent-conductor-*` → `skills/weave-ai-*`, `skills/manifest.json`,
  `skills/README.md`, `packages/core/src/workers/home.ts`, `packages/core/src/artifacts/kit.ts`.
- **Docs/branding**: `README.md`, `CLAUDE.md`, `CLA.md`, `LICENSE`, `ee/`, `docs/**`,
  `templates/*.tmpl`, `examples/plugins/README.md`.
