## Context

`Session` (packages/agent/src/session.ts) already writes `{id, parentId, type:'message', message}` lines and reads them as one chain. The loop (`loop.ts`) builds the request from `session.messages` each step and records `contextTokens` from the response's `prompt_tokens`. The engine already reacts to `session.compaction.started|completed` events and calls `adapter.compactSession` and `modelContextWindow` (packages/core). The run engine re-queues family `resource`, so a compaction that cannot help must end as `context_overflow`/`resource` only after one attempt (already the error table's meaning). Work lands as two reviewable halves: (a) sessions, tokens, compaction; (b) pruning, instructions, skills, caching.

## Decisions

1. **Tree, one active path.** Entries: `message`, `compaction {summary, firstKeptEntryId, tokensBefore, tokensAfter, files:{read,modified}}`. `Session.context()` returns `[summaryMessage, ...messages from firstKeptEntryId to leaf]` where the summary message is a `user` message prefixed `[Conversation summary]`. The file keeps everything (append-only); compaction only moves what the projection starts from. Fork copies the file with a new session id and header (`forkSession`), leaf unchanged. Loading tolerates old linear files and a torn last line as today.
2. **Cut point.** Walk back from the leaf accumulating estimated tokens until `keepRecentTokens` (20k), then move the cut earlier to the nearest *turn boundary*: the first message of the kept span must be a `user` message, or an `assistant` message whose preceding message is not a `toolResult` chain it depends on. Concretely: a valid cut index `i` is one where `messages[i]` is `user`, or `assistant` (never `toolResult`). An assistant tool-call message and its results are contiguous, so cutting before an assistant or user message can never orphan a result. If no valid cut exists inside the budget (one huge turn) the cut moves later to the newest valid boundary, and if none exists compaction is skipped with a log. A property test over random histories asserts every kept span begins on a valid boundary and every kept `toolResult` has its `toolCall` in the kept span.
3. **Summary.** One non-streamed-to-UI request through the same profile, same model, no tools, system prompt = fixed summariser instruction, user message = previous summary (when there is one) + serialised span with tool results cut to 2000 characters, asking for the fixed template (Goal, Constraints, Progress done/in progress, Decisions, Files read/modified, Next steps, Critical context). File lists are accumulated deterministically from `read`/`write`/`edit` tool calls in the span, merged with the previous record, and appended to the summary by code, not by the model. Prompt caching writes are disabled for this request. The summary is capped at 8k tokens output. Failure (error, empty text) leaves the session untouched and logs; the turn carries on.
4. **Triggers.** Before every request: `estimate(system + tools + projected messages) > window − max(16384, maxOutputTokens)`. Reactive: `StepFailure` code `context_overflow` compacts once per turn and retries the step; a second overflow surfaces. Window comes from the resolved `contextWindowTokens` (the adapter already sets it from option → profile → discovery and passes it in `init.provider.params`). Unknown window: proactive compaction is off, one `log` warn, reactive path remains. Compaction emits `session.compaction.started` and `.completed {tokensBefore, tokensAfter}` events.
5. **`--compact` mode.** `bin.ts` accepts `--compact` on argv (the adapter's `compactSession` spawns the child the same way as a turn, with an init message carrying provider, session and window and no prompt); it compacts once, writes one `result`, exits. Reused code path with the loop's compactor. The API key travels on stdin only, as for turns. `compactSession` never throws and returns `{ok:false}` when the session file is missing or no provider is configured.
6. **Token accounting.** `tokens.ts` wraps js-tiktoken `o200k_base` (already a dependency via `@weave-ai/shared` `estimateTokens`) × 1.15 margin. The estimate of a request is `lastPromptTokens + estimate(messages appended since that response)` once a response exists; before the first response it is `estimate(system) + estimate(JSON of tool specs) + estimate(messages)`. The tool schemas are therefore always in the number. `firstRequest` and `contextTokens` continue to come from real usage.
7. **Pruning.** `prune.ts` is a pure function on the projected message list: when the estimate exceeds 70 % of the window, walk from newest, keep the newest 40k tokens of tool results, and replace older tool result texts with `[output pruned; N chars, re-run if needed]` if the total saving is ≥ 20k; otherwise return the list unchanged. Below 70 % nothing changes so the cached prefix stays byte-stable. The session file is never rewritten. Error results and the newest result of each tool name are never pruned.
8. **Instructions.** `instructions.ts`: after a successful `read`/`edit`/`write` of a path, find `AGENTS.md` files from the path's directory up to the worktree root not already loaded this session (a set rebuilt on resume from the tool calls in the projected history) and append `[instructions from <path>]\n<text>` (32 KiB cap) to that tool result, before it is persisted. The root `AGENTS.md` is already in the system prompt and is marked loaded.
9. **Skills.** `skills.ts` scans `<home>/.agents/skills/*/SKILL.md` (frontmatter `name`, `description`), lists `name: description` lines in the system prompt after the AGENTS text, and registers a `skill` tool (`{name}` → body plus the skill directory). Unknown name returns the list. `restricted` mode keeps `skill`. Frontmatter parse is a small dependency-free reader.
10. **System prompt budget.** The fixed preamble grows only by tool conventions and stays ≤ 1200 tokens excluding AGENTS.md and the skill index; a test computes it with the estimator and also asserts two consecutive request bodies have an identical system message (dates and cwd stay in the first user message, as today).
11. **Caching.** Two additive compat fields in `ProviderCompatSchema`: `promptCache: 'none'|'key'|'anthropic'` (default `none`) and `cachedTokensField` (dotted path, default `prompt_tokens_details.cached_tokens`, also reading `prompt_cache_hit_tokens` as now). `key` sends `prompt_cache_key = sessionId`; `anthropic` converts the system message and the last user message to content-block form with `cache_control:{type:'ephemeral'}` and marks the last tool. Presets are not flipped to a caching mode unless a fixture proves it (project rule): all stay `none` except where the design already says; this change ships the mechanism and tests it against the mock provider. Compaction requests send neither.
12. **Retention.** At child start (turn or compact), files in `sessionsDir` other than the current session whose mtime is older than `sessionRetentionDays` (option, default 30, `0` disables) are deleted, along with their spill dirs are left to the existing run-dir handling. A failure to delete is logged, never fatal.
13. **Adapter.** `capabilities.forkSessions = true`; `forkSession` copies the JSONL under a new id in the same sessions dir and returns a new ref; `describeSession` reports the id and whether the file exists; `contextCompactionAt` is declared on the capabilities (a fraction the engine's percentage policy uses; set to 0.85 of the window to sit below our own hard trigger). Events `session.compaction.*` pass through `events.ts`.
14. **Weaver scale.** The weaver's tool set comes from the run-scoped MCP server exactly as for workers, so no adapter change is needed for it. Tests use `mockMcp` extended to serve ~40 `weave_*` schemas, plus a 500+ message session fixture generated in the test, and a scenario where the mock model calls `weave_human_send`. The guarantee "the last human message survives" holds because the cut is on a `user` boundary at or before the newest user message only when the kept span includes it: the compactor always keeps from the newest user message onward, even beyond `keepRecentTokens`.

## Risks / Trade-offs

- A summary from a weak model can lose facts: file lists are deterministic and the previous summary is fed back, but quality is only checked with the mock provider here; the weaver runs a live check afterwards. Unverified until then.
- Estimation error of up to ±20 % on non-OpenAI tokenizers is absorbed by the 1.15 margin and the reactive path.
- Not changing the engine means `contextCompactionAt` semantics are as the engine already defines them; read its handling during apply and record what it does.
