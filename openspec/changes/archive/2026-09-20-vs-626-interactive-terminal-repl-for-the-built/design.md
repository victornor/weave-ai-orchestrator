## Context

`runAgentTurn(init, io, signal, {steering})` (`packages/agent/src/loop.ts`) is the whole loop: it takes the child's `InitMessage`, emits events and partials through a `LoopIO`, honours an `AbortSignal` and a `SteeringQueue`, and returns a `ChildResult`. The daemon's adapter builds that `init` from workspace config and spawns `bin.js`; nothing else needs a process. Sessions are JSONL via `Session`; skills come from `<run.cwd>/.agents/skills`; the MCP client (`createMcpClient`, `testMcpServer`) is transport-agnostic. `weave chat` (talk to the conductor) and `weave agent` (run-token commands) already exist in the CLI.

## Goals / Non-Goals

**Goals:** a REPL that behaves like the child (same loop, same tools, same session format) with no daemon; every piece of command handling and rendering testable as a pure function; a pty test that drives the real binary against `testkit/mockProvider`.
**Non-Goals:** a full-screen TUI; cost display; use as the weaver's runtime; a daemon route; OAuth/approvals; plugin commands.

## Decisions

1. **Name.** `weave repl`, and a `weave-agent` shim. The ticket's `weave agent` is taken (agent-facing group, needs `AC_RUN_TOKEN`), `weave chat` talks to the conductor. `weave-agent` is what the design doc already calls it. The shim targets a new tiny `packages/cli/dist/repl-bin.js` (it prepends `repl` to argv) so the existing `exec "node" "target" "$@"` shim shape and `readCliShimTarget` keep parsing; `writeCliShims` writes both shims, and upgrade already calls it, so the bin appears on PATH after an upgrade with no step.
2. **In-process, not a child.** The REPL calls `runAgentTurn` directly. Cancel is an `AbortController`, steering is the `SteeringQueue`, the result's `exitCode` feeds `-p`. A child would add an NDJSON pipe and gain nothing: the human's terminal already owns the process group and Ctrl-C. The loop's own safeguards hold (bash env is `toolEnv` plus `PATH/HOME/LANG/TERM`, never the provider key; `shellEnv(init.toolEnv, apiKey)`). The loop is exported from `@weave-ai/agent` as `runAgentTurn`; `bin.ts` is untouched.
3. **Layering (`packages/agent/src/repl/`).** The package also gets its own small entry (`repl/bin.ts`, with a hand-rolled argv parser) so tests and a bare install can start the REPL without the CLI; the installed commands go through the CLI's `weave repl`. `events.ts` (pure: loop event/partial → `Line[]` styled spans, edit as diff, bash command plus streamed output), `commands.ts` (pure: parse and execute slash commands against a `ReplState`, returning `{output, state}`), `config.ts` (resolution below), `sessions.ts` (list/resume from a directory), `terminal.ts` (raw-ANSI line editor: history, tab completion, Ctrl-C/D, redraw around streamed output). Node `readline` is used for line editing and history with a custom `completer`; no library. The renderer's output is a plain string array, so tests assert bytes without a pty; the pty test proves only the wiring.
4. **Configuration, in order.** (a) `--provider <id> --base-url <url> [--model m]` build a profile in memory (preset `openai-compatible`, or `--preset`). (b) Otherwise the nearest `workspace.yaml` from the cwd (`--workspace-dir` overrides): its `providers:` and `mcpServers:` parsed with the shared zod schemas, its state dir from `resolveWorkspaceStateDir`. (c) `~/.config/weave/agent.yaml` (`provider`, `model`, `permission`, `providers`, `mcpServers`), read only: nothing is written back (no `/model save` in this change), and never keys. **Keys**: `WEAVE_LLM_<PROVIDER>_KEY` in the environment first; else the workspace's `secrets.enc`/`secrets.key` read locally through a read-only AES-256-GCM opener in `@weave-ai/agent` (compatible with core's `createSecretStore`, proven by a cross-package test in `packages/server`); else, on a TTY with no key, a hidden prompt held in memory only. A key is never written, never in argv, never printed (the renderer and `--debug` redact it), and never in the bash tool's env (the loop already guarantees this). The daemon is never contacted: reading the workspace files is enough, so `GET /providers` is not used and cannot leak a value.
5. **Sessions.** Directory `<data home>/weave-agent/sessions/` (`~/.local/share/weave-agent/sessions` by default, `WEAVE_AGENT_HOME` overrides). A worker's sessions are under `<configHome>/weave-agent/sessions` of a workspace, a different tree the REPL never scans, so a ticket session cannot be listed or resumed by accident. The format is unchanged (`Session`); new REPL files get `origin:"repl"` in the header line (an additive field, unread by old code) and a `{type:"repl",model,provider,at}` bookkeeping line per turn, an entry type `Session.open` already ignores. `/sessions` scans headers only (id, cwd, created, first user line, message count, last `repl` model) and filters on the header's `cwd`; `--all` widens. Retention: the loop already sweeps the file's own directory at 30 days; the REPL passes the same option.
6. **Skills.** `init.skillRoots?: {dir, source}[]` is an additive optional field; when absent the loop uses `<run.cwd>/.agents/skills` exactly as today. The REPL passes project (`<cwd>/.agents/skills`) and user (`~/.agents/skills`, `~/.config/weave/skills`) roots; `/skills` prints name, description and source. Name collisions: the project root wins.
7. **MCP.** The loop connects per turn from `init.mcpServers`; `/mcp` connects each configured server once (`createMcpClient` + `listTools`, the path `testMcpServer` uses, 15 s bound) and prints connected/failed, the error, and the tool count; `/mcp <server>` lists names and descriptions. Sources: workspace `mcpServers` (secret `${NAME}` references resolved from the workspace store or env) and `agent.yaml`.
8. **`/model`.** With no argument: provider, model, resolved params (`resolveProvider`). A picker: the profile's static models merged with discovery (`GET {baseUrl}{modelsPath}`, 10 s, failure falls back to static with a note). Parameters use the schema that already exists (`ProviderParamsSchema` via `paramsFromOptions`): `/model temperature 0.2`, `/model effort high`, `/model topP`, `maxOutputTokens`, `contextWindowTokens`; an invalid value is refused with the schema's message and nothing changes; `/model unset <key>` removes one; an unset key is never sent. `effort` maps through the compat block (`effortParam`/`effortMap`) in `buildRequest`; it is `init.run.effort`, not a param. Changes apply from the next request and live in `ReplState` for the session (not saved back to a file).
9. **`/permissions`.** Shows and sets the existing `auto | restricted | bypass`. **Default `auto`**: all core tools and MCP, file tools confined to the cwd and the REPL home, bash deny patterns, no approval prompts (the mode a human already accepts for a worker). `bypass` needs an explicit `/permissions bypass` or `--permission bypass`; `restricted` gives a read-only session. No new mode.
10. **Terminal behaviour.** Ctrl-C during a turn aborts it (the loop returns exit 143, persists the assistant text and a synthetic interrupted tool result, so the session loads); at an idle prompt the first Ctrl-C clears the line and prints a hint, a second exits. Ctrl-D on an empty line exits. Text typed while a turn runs is pushed to the `SteeringQueue` and echoed dim as "queued". `-p` runs one turn with no prompt, prints only the final text on stdout (events go to stderr with `--verbose`), and exits with `result.exitCode`. Colour only on a TTY; `NO_COLOR` respected.
11. **Session header `cwd` and tools.** The turn's `run.cwd` and `worktree.path` are both the process cwd, so confinement roots are the cwd plus the REPL home (spill directory under it); the nested `AGENTS.md` loader and the home `AGENTS.md` pin work on the cwd. The system prompt text is the cwd's `AGENTS.md` when present.

## Risks / Trade-offs

- **Duplicated secret-opening crypto (about 15 lines)** to keep the CLI off `@weave-ai/core` (and its native SQLite). Mitigation: the cross-package round-trip test fails if core's format changes.
- **In-process loop:** a loop crash takes the REPL down; mitigated by the loop's own try/catch (`agent_crashed` result) and by session appends being fsynced per line.
- **Reading `workspace.yaml` directly** duplicates the daemon's config path logic; it uses the shared schemas and `resolveWorkspaceStateDir`, and fails soft to standalone mode with a printed note.
- **Real terminal behaviour** (wide characters, resize, slow links) is only covered by the pty test on a Linux pty; the live check is the weaver's.
- **Unverified:** a real provider turn from a real terminal. Not run by this ticket.
