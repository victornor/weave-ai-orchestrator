## Decisions
- **Sandbox is constant, approvals stay per mode.** `buildArgs`: `bypass` → `--dangerously-bypass-approvals-and-sandbox` only; otherwise `--sandbox danger-full-access` on new turns and `-c sandbox_mode="danger-full-access"` on resume/fork (resume does not accept `--sandbox`), plus `approval_policy=on-request` for `auto` as today. `postureFor`: `danger-full-access` for all modes; approval policies unchanged (`never` for bypass/restricted, `on-request` for auto).
- **`restricted`:** captain asked for "all", so it gets full access too. Its read-only guarantee is no longer OS-enforced; only approval declines and the role's prompt limit it. Accepted trade-off.
- **Dead code:** VS-685 writable roots only apply under `workspace-write`; delete `gitdir.ts`, `sandboxWritableRoots`, the `writableRoots` build option and their tests. VS-704 has no codex-specific workaround in the adapter (its design concerned the sandbox environment); nothing to remove there beyond what grep finds.
- **Verification:** unit tests on `buildArgs`/`postureFor`. A real-CLI smoke test would use the owner's OAuth login, which repo rules forbid running from a ticket, so it is reported as unverified rather than run.
