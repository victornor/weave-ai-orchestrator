## 3. `ChannelManager`: restart a single channel kind

- [x] 3.1 Refactor `ChannelManager.start()` (`packages/server/src/channels.ts:49-75`) so its per-kind body (adapter lookup, `validateConfig`, `ensureChannelRow`, `adapter.start`, bookkeeping into `running`/`adapters`) becomes a private `startOne(kind, config)` helper that `start()` calls for each configured kind, unchanged in behavior. Implementation note: `startOne` computes its own effective config via a new `effectiveConfig(kind)` (merging `resolveTelegramToken` in for `'telegram'`), rather than taking `config` as a parameter — `start()` itself must resolve the secret-store token on daemon boot too, not only on a live `restartChannel` call, or a token that lives only in the secret store would never start the channel until the route happened to be hit.
- [x] 3.2 Add `async restartChannel(kind: string): Promise<void>`: stop and remove any running handle for `kind` first, then call `startOne(kind)` (which resolves the current effective config itself). Verify with a `packages/server/test/channels.test.ts` case: a running fake Telegram adapter is stopped and a new one started when the resolved token changes; calling `restartChannel` with no resolvable token stops a running adapter and does not start a new one.
